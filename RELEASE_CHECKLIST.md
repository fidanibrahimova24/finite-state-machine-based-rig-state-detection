# Public-release checklist

- [ ] Confirm repository name and public author/affiliation text.
- [ ] Confirm MIT licensing is compatible with employer, university, consortium, and data-provider obligations.
- [ ] Add the paper/software DOI or preferred citation when available.
- [ ] Run KUBD, 16A, 56-32, and 58-32 from raw input through all stages.
- [ ] Archive each well's mapping, native units, bit-size schedule, QC reports, software commit, and output hash.
- [ ] Obtain independent DDR/manual interval labels or clearly limit claims to logical consistency/robustness.
- [ ] Report per-state precision, recall, F1, confusion matrix, duration-weighted accuracy, and unknown/data-gap coverage.
- [ ] Verify connection markers, MSE gaps, and state filters in Chrome and Firefox.
- [ ] Remove raw/proprietary well data and large generated outputs from Git history.
- [ ] Create a tagged release only after cross-well regression passes.
